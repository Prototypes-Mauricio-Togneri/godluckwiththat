# Research node visuals

Source: [research.md](./research.md) → TODO, item 2: "Visual polish on research nodes (per-node icons, progress bar on active nodes)".

## Goal

Give every node in the research modal its own icon, and show a progress bar on nodes whose research is running. The current status styling (completed / active / available / locked), the cost tooltip, and the five-nodes-per-row layout must keep working.

## Current state

**Node rendering** (`src/components/modals/research_modal.vue`)

- Each subcategory is a header (name, effect text, "Accumulated" pill; 169-173) above a horizontal chain of 5 nodes joined by arrow connectors (174-212).
- A node (177-210) has two rows: the name (185-187), then a second row (188-203) that depends on status:
  - completed → green checkmark `IMG_OTHER_COMPLETED`, `alt=""` (189)
  - active → text countdown `formatTime(ui.academy.activeTimers[rKey]?.remainingSeconds ?? 0)` (190-192)
  - otherwise → three cost items: resource icon from `IMG_RESOURCE_MAP` and a short amount, red when unaffordable (193-202)
- Available and locked nodes also show a hover tooltip with the full cost. It is absolutely positioned below or above the node (204-209), so the node must not get `overflow: hidden` in those states.
- Status comes from `nodeStatusMap` (41-58): completed, else active, else locked if the previous tier isn't done, else available. No node, subcategory or category has an icon today.
- Status CSS (407-438):
  - completed: green border and tint
  - active: accent border plus an infinite `research-pulse` outline animation with `will-change: outline` (412-422)
  - available: brighter border and a pointer cursor
  - locked: header and second row at opacity 0.5 (435-438)
  - The node box (387-398) has `min-width: 130px`, padding `0.55rem 0.7rem` and radius `0.25rem`.
- The scroll area hides horizontal overflow (300-306). If a row is wider than the modal (`90vw`, max `960px`; 236-251), it gets clipped, not scrolled. The second row is `nowrap`, so the three cost items set each node's minimum width: about 130px on tier 1 and about 160px on tier 5. By estimate, a full row starts clipping on windows narrower than about 1000px.

**Progress data** (already in the UI, no engine change needed)

- `ui.academy.activeTimers[key] = { remainingSeconds, duration }` is kept up to date in `src/components/screens/game_screen.vue`:
  - by the fast sync `syncTimers` (research block 512-528), which runs every 50 ms (`UI_SYNC_INTERVAL`, 1197; rAF loop 1337-1376)
  - by the full sync `syncAcademy` (788-806)
  - The initial shape is at 361-365.
- Durations come from `Cost.toSeconds` (`src/js/models/cost.js:93-102`). Today they run from about 5 s (tier 1) to about 46 s (tier 5) at 1x, and a third of that at 3x. At 20 updates per second, a bar moves visibly and smoothly without a CSS transition.
- The sync stops while the game is paused, so a bar freezes during a pause, which is the right behavior.

**Reusable progress visuals**

- Construction button fill (`src/assets/styles.css:351-374`): `.action-btn--constructing::before` is a gold `rgba(184, 148, 62, 0.25)` overlay whose width is the CSS variable `--progress`. The countdown sits on top of it with `position: relative` (376-385).
  - Used by `src/components/buildings/base_card.vue`: progress is computed as `1 - remaining / duration` with a guard for duration 0 (126-131) and bound at 187.
  - Also used by `headquarters_card.vue` (33-45, 106-107, 133-134).
  - The rule is specific to buttons (sizes are in container units), so it can't be put on a node as is. The same approach can be reused.
- Thin bars:
  - `.resource-bar` / `.resource-bar-fill` (`styles.css:819-848`): a 0.25rem track on the header resources.
  - `.timer-bar` / `.timer-bar-fill` (`challenge_detail_modal.vue:99-101`, CSS 235-246): a 3px accent bar.
- Greyscale for "not yet" art: `.building-thumb-unbuilt { filter: grayscale(1) }` (`base_card.vue:312-315`) and `.locked-icon` (`game_screen.vue:2233-2241`).
- No progress UI in the project uses ARIA (`role="progressbar"` and `aria-value*` appear nowhere). The visible countdown serves as the text version.

**Assets and the generator**

- Image formats in `public/img/`:
  - Paintings and scenes are 512×512 JPGs: `buildings/*/`, `punishments/`, `blessings/` and `other/portal.jpg`.
  - Small icons are PNGs with transparency: `other/*.png` and `seasons/*.png` are 128×128; `resources/*.png` and `units/worker.png` are 64×64.
  - The icons are painted, cartoon-style objects with dark outlines and soft shading, 3-22 KB each (e.g. the `other/build.png` hammer, the `resources/knowledge.png` book). Git history doesn't record how they were made (every commit is titled "Improvements").
- Code never hardcodes paths. `src/js/engine/assets.js` is generated by `npm run generate-assets` (`scripts/generate-assets.js`); see `docs/javascript.md` → Asset Paths.
- **Generator catch:** it only emits folders listed in `GROUP_LABELS` (18-30; the emit loop is at 108-140). If a new `public/img/research/` folder isn't added there, it is skipped without any warning: the files ship, but no constants or map are generated.
- Constant names come from `toConstantName` (57-73): `research/food_production_1.png` becomes `IMG_RESEARCH_FOOD_PRODUCTION_1`. The function makes the folder name singular by dropping a trailing `s`, so the folder must be named `research`, not `researches` (which would give `IMG_RESEARCHE_…`).
- Each lookup map has its own hardcoded code in the generator:
  - `IMG_RESOURCE_MAP` uses the file name as the key (124-130, 142-154).
  - `IMG_PUNISHMENT_MAP` turns the snake_case file name into a camelCase key with `/_([a-z])/g` (132-138, 156-168). That regex leaves `_1` untouched, so `food_production_1` would become `foodProduction_1` instead of the research key `foodProduction1`.
- Keys and tree:
  - Research keys are camelCase plus the tier digit, e.g. `foodProduction1` (`src/js/engine/enums.js:89-186`). Subcategory keys are camelCase, e.g. `foodProduction` (69-86).
  - `RESEARCH_TREE` is at `src/js/engine/constants.js:467-691`. `RESEARCH_MODAL_TREE` (694) is the same tree without the Disasters category.
  - In total: 5 categories, 18 subcategories, 90 researches. The 15 Disasters researches are hidden in the modal.
- Research events in the events list use the knowledge book icon (`src/js/engine/state.js:1264`).

**Constraints**

- `docs/ui.md`:
  - colors only as `rgba()` (no hex)
  - `border-radius` in `rem`
  - CSS repeated across `.vue` files goes in `src/assets/styles.css`; CSS for one component stays in its scoped block
  - use the `frontend-design` skill for UI changes
- Vue components have no unit tests (`docs/testing.md` → What Is Not Tested). Only engine, model and i18n JavaScript is tested.
- Touch devices see a "not available on mobile" notice (`docs/architecture.md:5`), so "narrow layout" means a narrow desktop window, not a phone.
- The language comes only from the browser's language setting (`src/js/i18n/localized.js:21`). The longest single words in research names are 16 characters in Italian ("fiancheggiamento") and 14 in English ("Leatherworking").

## Decisions

### A. Icon granularity

1. **90 icons, one per research.** Matches the TODO literally, and every research name is a concrete object (Wheel, Plough, Silos…). Costs 90 pieces of art.
2. **18 icons, one per subcategory, plus a tier marker (I-V or pips) in the node.** Five times less art, but all five nodes in a row show the same picture, so it only half meets "its own icon".
3. **5 icons, one per category.** Cheapest, but every node in a tab looks the same, so the icon adds almost nothing.

**Recommendation: 1.** The 15 Disasters icons can stay as placeholders until that tab ships (step 1), so only 75 final icons are needed now.

### B. Art source and format

1. **Match the existing small icons:** 128×128 PNG with a transparent background, in the painted cartoon style of `public/img/other/*.png`, optimized to about 20 KB or less. Files go in `public/img/research/<subcategory_snake>_<tier>.png`, e.g. `food_production_1.png`, mirroring the enum name `RESEARCH_FOOD_PRODUCTION_1`. Total cost is about 1-1.5 MB.
2. **Same, but 64×64 like `resources/`.** Half the bytes, but the icons look soft if they're ever shown larger than about 2rem or on 3x screens.
3. **JPG scenes like the punishments.** No transparency, and the picture can't be read at about 1.5rem.

**Recommendation: 1.** Open question: the existing art pipeline isn't documented. Confirm with the author that someone can produce 75-90 icons in the current style before the art is commissioned.

### C. Icon placement and per-status look

Placement:

1. **Icon at the start of the name row (about 1.5rem square), with the cost/timer row unchanged below it.** The node gets a few pixels taller. Its width barely changes, because the cost row already sets the width; only the longest Italian names push it wider.
2. **Icon in a left column spanning both rows (about 2rem).** Looks most like a card, but adds about 2.5rem to every node, so a row of tier-5 nodes overflows and gets clipped.
3. **Icon centered on top of the node.** Shows the picture most clearly, but every row grows about 2rem taller, which means more scrolling in the 6-row Resources tab.

Status look:

1. **Locked: greyscale on top of the existing 0.5 opacity. Available, active and completed: full color.** Reuses the greyscale look of unbuilt buildings.
2. **Also greyscale nodes that are available but unaffordable.** Adds a signal, but it flickers as resources tick up, and the red amounts already show it.
3. **No extra treatment beyond the opacity the icon inherits.**

**Recommendation: placement 1, status look 1.**

### D. Progress bar style

1. **Fill the node like the construction button.** A gold `::before` overlay (`rgba(var(--color-accent-rgb), 0.25)`) grows left to right behind the content, with its width set by `--progress`. Players already know this look from buildings. Two side requirements:
   - `overflow: hidden` on active nodes only. This is safe because the cost tooltip never renders on active nodes.
   - `position: relative` on the node's rows so the text paints above the fill.
2. **Thin bar (about 0.1875rem) along the bottom edge of the node, like the challenge timer.** Doesn't affect text contrast, but it's a smaller cue and new to this modal.
3. **Small bar next to the countdown in the second row.** Needs width the row doesn't have.

Countdown text: **keep it.** Construction buttons show both the fill and the time, and the text is the only accessible form of the progress.

Pulse animation: **drop it** on active nodes, together with `will-change: outline`, and keep the accent border. The fill already shows activity and moves visibly at today's 5-46 s durations. This also removes up to 6 never-ending animations per tab.

**Recommendation: 1, keep the countdown, drop the pulse.** If the fill hurts the readability of the timer during the design pass, fall back to 2.

### E. Generator change

1. **Add `research: 'Research'` to `GROUP_LABELS`, and add a third map, `IMG_RESEARCH_MAP`, by copying the punishment code.** Change the key conversion to also handle digits: `/_([a-z0-9])/g` turns `food_production_1` into `foodProduction1`. Smallest change, same pattern as the two existing maps, and it doesn't change punishment keys (no digits there).
2. **Replace the two hardcoded map blocks with a small table (folder → map name, key style) and add research to it.** Cleaner, but rewrites working code beyond this task.
3. **Only add the folder to `GROUP_LABELS`, then hand-write `RESEARCH_IMAGE_MAP` in `constants.js` like `BUILDING_IMAGE_MAP`.** No map code in the generator, but 90 imports and entries to keep in sync by hand.

**Recommendation: 1.** All three options need the `GROUP_LABELS` entry.

### F. Where the progress formula lives

1. **A small pure function in `src/js/engine/utils.js`, e.g. `timerProgress(remainingSeconds, duration)`.** Returns 0-1, clamped, and 0 when the duration is missing or ≤ 0. It can be unit-tested (Vue files can't). Costs one new export.
2. **An inline function in the modal, as `base_card.vue` does.** No new export, but also no test.
3. **A getter on the `Research` model, plus a `progress` field in both UI syncs.** Testable, but it changes the 20 fps sync code in two places to carry a value the UI can work out itself.

**Recommendation: 1.** Switching `base_card.vue` and `headquarters_card.vue` over to it is a separate cleanup and not part of this task.

## Tests

- `tests/engine/utils.test.js`: new `describe('timerProgress')` with these cases:
  - returns 0 when remaining equals duration
  - returns 0.5 halfway through
  - returns 1 when remaining is 0
  - clamps to 0 when remaining is greater than duration, and to 1 when remaining is negative
  - returns 0 when duration is 0, negative or `undefined`
- `tests/engine/constants.test.js`: new `describe('RESEARCH_TREE and IMG_RESEARCH_MAP consistency')`, next to the existing `BUILDING_CLASS_MAP` consistency block:
  - every research key in `RESEARCH_TREE` (all 90, Disasters included) has an entry
  - the map has no keys outside the tree (exactly 90)
  - every value starts with `/img/research/` and ends with `.png`
  - This also fails if the generator wasn't re-run after files were added, or if the folder is missing from `GROUP_LABELS`.
- No component test: the project has no setup for testing Vue components (no `@vue/test-utils`), so the template and CSS are checked by hand (Verification).
- No generator test: the generator writes `assets.js` as soon as it's imported, so it can't be unit-tested without a refactor. The consistency test covers its output.

## Out of scope / risks

Out of scope:

- Using the research icons in the events list (`state.js:1264` uses the knowledge book) or on the Academy card.
- Making nodes reachable by keyboard. They're clickable `<div>`s today, which is an existing gap.
- A shared progress-fill style used by both buildings and research.
- The other research TODOs: balancing, the tier check in the engine, and Academy downgrade.

Risks:

- Art is most of the work: 75-90 icons in one consistent style. Until it's done, the placeholders look the same as each other. The Disasters icons can't be seen in the game until that tab ships.
- The balancing pass (TODO item 1) may make research much longer. The fill would then move slowly, and the dropped pulse was the only other sign of activity, so revisit decision D at that point.
- Layout: rows already clip on narrow windows (about 1000px, estimated). The icon must not make that worse (step 8).
- Weight: about 1-1.5 MB added to `public/`. Images aren't preloaded anywhere, so the icons may pop in the first time a tab is opened.
- Adding or swapping files without re-running `npm run generate-assets` makes the consistency test fail, which is intended.
