# Architecture & Design

Vite + Vue 3 single-page application using Composition API (`<script setup>`). No Vue Router — screens switch via `v-if` on a `currentScreen` ref in `app.vue`.

**Screen flow**: Home → Game (via `start` event with optional saved data payload), Home → Settings, Home → About (each sub-screen emits `close` to return Home). The home screen shows a single start button — "Continue" when a saved game exists, otherwise "New Game" — plus Settings and About. On touch devices (`pointer: coarse`) the start button is hidden and a "not available on mobile" notice is shown. In dev builds (`IS_DEV`) the home screen starts the game immediately on mount (continuing the saved game if one exists).

- **Settings screen** (`settings_screen.vue`) — full-screen version of the Settings Modal controls (music, sound effects, autosave toggle and interval), reachable before a game starts.
- **About screen** (`about_screen.vue`) — app version (`__APP_VERSION__`), a feedback mailto link, and buttons opening the **Changelog Modal** (`changelog_modal.vue`, renders `src/assets/changelog.md` with `marked` after stripping inline HTML tags) and the **More Games Modal** (`more_games_modal.vue`, links to other games).

**Modal pattern**: Parent controls visibility with `v-if`. Modal component emits `close` on backdrop click (`.self` modifier) or close button. Mounts/unmounts cleanly. Escape is routed through `escape_stack.js` (`src/js/engine/`): each modal calls `pushEscapeHandler` on mount and `removeEscapeHandler` on unmount, and a single capture-phase window listener calls only the most recently pushed handler and stops the event, so the topmost modal handles Escape and modals underneath (and the game screen's pause toggle) never see it. Blocking modals push a no-op handler. The pause modal is the exception: it registers only a focus layer, so Escape falls through to the game screen's pause toggle, which closes it. Keyboard focus is kept in the topmost modal by `focus_stack.js` (`src/js/engine/`): each modal binds a template ref to its root element, calls `pushFocusLayer` with it on mount and `removeFocusLayer` in `onBeforeUnmount` (the ref is already cleared by `onUnmounted`); everything outside the topmost pushed element (header, board, modals underneath) gets the `inert` attribute, so Tab, Enter and Space cannot reach controls an overlay only covers visually. A `MutationObserver` on the topmost layer's ancestors re-applies the marks when an element is added beside the path (e.g. a building card unlocked behind a building help modal). Only elements the module marked are restored when the topmost modal changes. Closing the topmost modal gives focus back to the element that had it when that modal opened (if still on the page); a modal closing underneath leaves focus alone.

### Pause Modal (`pause_modal.vue`)

Centered overlay with "PAUSED" title, decorative rule, and six stacked buttons:
- **Resume** — emits `close`, resumes the game
- **Save** — emits `save`, triggers `saveGame()` in `game_screen.vue` which calls `persistGame()` and closes the modal
- **Load** — emits `load`; `loadGame()` in `game_screen.vue` restores the save with `State.fromJSON()` first and restarts with the restored state, or, when the save is missing or cannot be restored, keeps the current game and the pause menu open and flashes a red "Load Failed" indicator (disabled when no saved game exists)
- **Settings** — emits `settings`, opens `SettingsModal`
- *(decorative rule separator)*
- **Restart** — emits `restart`, opens a confirm modal (does not restart directly); confirming deletes the saved game and starts a new one; danger-styled
- **Quit** — emits `quit`, opens a confirm modal (does not quit directly); danger-styled

### Settings Modal (`settings_modal.vue`)

Centered overlay (same pattern as other modals) opened from the pause modal. Contains toggle switches and autosave configuration:
- **Music toggle** — on/off switch, persisted via `storage.musicEnabled`
- **Sound Effects toggle** — on/off switch, persisted via `storage.soundEnabled`
- *(decorative rule separator)*
- **Autosave toggle** — on/off switch, persisted via `storage.autosaveEnabled`
- **Autosave interval** — +/− buttons to adjust interval in minutes (clamped to `AUTOSAVE_MIN_INTERVAL`–`AUTOSAVE_MAX_INTERVAL`), persisted via `storage.autosaveInterval`
- Emits `close` on backdrop click, close button, or Escape key

### Building Help Modal (`building_help_modal.vue`)

Centered overlay (same pattern as pause modal) showing information about a building. Rendered inside `base_card.vue` via `v-if` on a local `showHelp` ref. Props: `nameKey` (i18n key for the title), `buildingKey` (indexes into `buildingHelp.{key}` for the description), and `img` (building thumbnail path). Layout: uppercase building name title, decorative rule, horizontal body with large thumbnail image (9rem) alongside description paragraph, and a "CLOSE" button. Emits `close` on backdrop click, button press, or Escape key.

### Modal Help Modal (`help_modal.vue`)

Generic help modal for overlay-on-overlay display (z-index 110, above the parent modal's z-index 100). Takes `title` and `body` props (pre-translated strings). Layout: uppercase title, decorative rule, description paragraph, and a "CLOSE" button. Follows the same animation pattern as other modals (rAF-driven `visible` class). Mounts after its parent, so it sits on top of the Escape stack and closes itself without affecting the parent modal. Used by `research_modal.vue` and `market_modal.vue` via their "?" help buttons.

### Confirm Modal (`confirm_modal.vue`)

Reusable confirmation modal (same overlay pattern). Props: `titleKey` and `descriptionKey` (i18n keys), optional `confirmKey` (i18n key for confirm button text, default `'modal.confirm'`). Layout: uppercase title, decorative rule, description paragraph, and a side-by-side button row — subdued "CANCEL" (gold) and red-styled "CONFIRM". Emits `confirm` or `close`. Used by `game_screen.vue` for quit confirmation, restart confirmation, and the "Clear all" past events action.

### Market Modal (`market_modal.vue`)

Centered overlay (same pattern as other modals) opened from the market building card. Injects `ui` and `actions`. A "?" help button (`.modal-help-btn`) sits left of the close button and opens `ModalHelpModal` with market help text. Displays a "Market" title, a resource summary bar showing current amounts for all tradeable resources and gold (each box has a tooltip with the full amount), a controls row with the current trade fee percentage and a trade-amount selector, and a scrollable list of trade rows (one per tradeable resource: Food, Wood, Stone, Copper, Iron) under Sell/Buy column headers. The trade-amount selector (−/+ buttons) steps through 100, 1000, 10000, … up to the storage cap (`MARKET_TRADE_AMOUNT` × 10ⁿ), clamps to the largest option when the cap shrinks, and persists the choice via `storage.tradeAmount`. Each row shows the resource icon and name, a sell button (+gold gain) and a buy button (−gold cost) for the selected amount. Both amounts come from `marketTradeQuote` in `utils.js`, the same per-lot pricing `Market.executeTrade` uses; the fee is applied in whole-percent integer math so exact results never floor one gold short. Buy/sell buttons use `.btn-gold`; disabled when unaffordable or storage cap would overflow (buying past the resource cap, or selling past the gold cap), with a tooltip explaining why. Insufficient amounts shown in red (`rgba(196, 80, 80, 1)`). Calls `actions.executeTrade(resource, direction, tradeAmount)` on click and plays the exchange sound. Emits `close` on backdrop click, close button, or Escape key. Visibility controlled by `showMarketModal` ref in `game_screen.vue`; opened via `inject('openMarketModal')` in `market_card.vue`, and closed automatically when the market's level drops below 1 (a punishment can destroy a mid-upgrade market).

### Challenge Detail Modal (`challenge_detail_modal.vue`)

Centered overlay opened when the player clicks a challenge future event. Injects `ui`. Displays the active challenge info: the challenge name as title (`challenge.name.{index}`), a countdown timer with a draining bar when the challenge is started (urgent styling under 60 s), and a requirements checklist (each requirement shown with a check/cross icon indicating whether it is currently met). Emits `close` on backdrop click, close button, or Escape key. Visibility controlled by `showChallengeModal` ref in `game_screen.vue`; opened by `handleEventAction()` when a future event with `action: 'openChallengeModal'` is clicked.

### Challenge Success Modal (`challenge_success_modal.vue`)

Blocking overlay (no close button, no Escape, no backdrop dismiss) shown when a challenge is completed successfully. Injects `ui` and `actions`. Displays two blessing choices side-by-side, each with an image, description, and effect details. The player must select one blessing. On selection, calls `actions.selectBlessing(index)`. Game is paused while this modal is visible. Controlled by `ui.challengeModal === CHALLENGE_MODAL_REWARD`.

### Challenge Failure Modal (`challenge_failure_modal.vue`)

Blocking overlay (no Escape, no backdrop dismiss) shown when a challenge fails. Injects `ui` and `actions`. Displays the punishment type with image and lists all penalty effects (faith loss, resource loss, worker loss, building level loss, productivity penalties). Has a single "Accept Punishment" button that calls `actions.acknowledgePunishment()`. Game is paused while visible. Controlled by `ui.challengeModal === CHALLENGE_MODAL_FAILURE`.

### Challenge Win Modal (`challenge_win_modal.vue`)

Blocking overlay shown when all 10 challenges are completed. Displays a portal image and a victory message announcing the portal is activated. Offers "Continue Playing" (resume playing) and "Return Home" (return to home screen) buttons. Emits `continue` or `quit`. Controlled by `ui.challengeModal === CHALLENGE_MODAL_WIN`.

### Game Header (`game_screen.vue`)

Top bar divided into 5 sections (no divider elements; spacing only):

1. **Year & Season** — season progress bar (gold in warm, blue in cold) above the year line: season icon (`<img>`, warm/cold), year label (`Josefin Sans`, small uppercase, muted) and numeric value (`Azeret Mono`). Hovering shows a rich tooltip with the season name and the current seasonal food production and wood consumption modifiers (e.g. "+20%").
2. **Resources** — preceded by a **productivity card** (`.productivity-box`, always visible) showing the current productivity ratio as a percentage with a fill bar (green at 100%, red when penalized; `.productivity-box--penalized` adds red-tinted border/background; its tooltip lists a food/wood deficit when net production is negative). Followed by resource boxes iterated via `HEADER_RESOURCES` constant (`v-for` loop). Only resources unlocked by the current HQ type are shown (controlled by `HQ_RESOURCE_UNLOCKS` in `constants.js`). Each resource rendered as a `.resource-box` (bordered container from `styles.css`) with three rows: icon image + current amount (`formatNumber`, red at storage cap or zero), the net per-second rate inline (`.production-rate`, `formatRate`, green/red), and a 0.25rem progress bar showing capacity fill percentage for bounded resources (green when net production is positive, red when zero or negative; the track is still rendered, empty, for unbounded resources so boxes align). A box is red-tinted (`.resource-box--penalized`) when its net production is zero or negative, or a bounded resource is at storage cap. Hovering a resource box reveals a rich HTML tooltip (`.resource-tooltip`) with a colon-aligned grid: amount (`formatNumberFull`), max capacity (bounded only), "Full in"/"Empty in" time estimate when the rate is nonzero, and — for food and wood — gross producing and consuming rates; production/consumption modifier percentages appear when nonzero. `UNBOUNDED_RESOURCES` (array in `constants.js`) controls which resources skip the progress bar, capacity and "full in" estimate.
3. **Game speed** — « / » buttons around a speed label (`1x`/`2x`/`3x`, from `GAME_SPEED_OPTIONS`), highlighted when above 1x. `speedUp()`/`speedDown()` in `game_screen.vue` write `state.meta.gameSpeed` (saved with the game); `gameDelta()` multiplies real elapsed time by it, so production, seasons, construction, research, events and challenge/blessing/punishment timers all run faster.
4. **Colony** — population (`current/max`), idle workers, territory (`current/max`), each shown as icon image + value inside a `.colony-box` (`flex-shrink: 0.3`, so it resists shrinking). The idle workers indicator includes a compact red dismiss button (`.dismiss-btn`, styled like `.worker-btn--minus`) that permanently removes idle workers to reduce consumption. Ctrl+click dismisses up to `BULK_WORKER_AMOUNT` (10). Disabled when no idle workers.
5. **Menu button** — hamburger icon (inline SVG), opens pause modal

Resource/colony items use `<img>` icons from `public/img/` (no text labels). Values use `Azeret Mono` (numeric font). All values sourced from `State` (see below), which initializes from `src/js/engine/constants.js` (factories) using values from `src/js/engine/balancing.js`.

**Keyboard**: Escape key toggles the pause modal (ignored when an `INPUT` or `TEXTAREA` is focused, on auto-repeated key events so holding Escape cannot flicker the menu, or when any other modal is open — the topmost modal takes Escape via the Escape stack). F9 triggers a manual save (auto-repeat ignored, so holding F9 saves once). Pause-menu Save, F9 and autosave all go through `persistGame()`, which writes `state.toJSON()` via `storage.writeSavedGame()`, marks a saved game as available only on success, and flashes a "Game Saved" or red "Save Failed" indicator. F3 toggles the performance overlay; showing it again starts a fresh sample. The overlay (`.perf-overlay`, a fixed `<pre>` in `game_screen.vue`) is visible by default in every build. Once a second it shows FPS, average frame gap, average `syncUI`/`syncTimers`/tick times, and JS heap used/limit when `performance.memory` exists (see `docs/performance.md`). It measures real time between animation frames (independent of game speed), leaves paused frames out, and discards the sample after a frame gap over 1 s (background tab, sleep).

### Building Grid (`game_screen.vue`)

Main content area displaying all 20 buildings in a 4-column layout. Each column represents a building category (Colony, Resources, Religion, Military) with a Josefin Sans uppercase header and building cards stacked in a 6-row grid (`grid-template-rows: repeat(6, 1fr)`, so every card gets 1/6 of the column height).

**Data source**: `BUILDING_GRID` constant from `constants.js` — array of column definitions, each with `headerKey` (i18n key) and `buildings` array of `{ key, img }` objects. `BUILDING_IMAGE_MAP` (also in `constants.js`) provides a flat key→image lookup derived from `BUILDING_GRID`, used for event icons. The `img` is a full path constant from `assets.js` (e.g. `IMG_BUILDING_HOUSE` → `'/img/buildings/misc/house.jpg'`). The `key` indexes into both `ui.buildings[key]` for the building snapshot and `'building.' + key` for the localized name.

**Dynamic component resolution**: `game_screen.vue` maps all 20 building keys to dedicated card components via `CARD_COMPONENTS` (e.g. `headquarters → HeadquartersCard`). Uses Vue's `<component :is>` in the grid loop.

**Building unlock restrictions**: Buildings are locked/unlocked based on the headquarters type. The `HQ_BUILDING_UNLOCKS` constant in `constants.js` maps each HQ type to the building keys it unlocks (per-tier, non-cumulative). Headquarters is always unlocked. `game_screen.vue` builds an `unlockedBuildings` computed set by iterating tiers up to the current HQ type index (UI-only gate; `State.levelUpBuilding` does not check it). Locked buildings render as a disabled placeholder card (same shell as `.building-card` but with `opacity: 0.4`) with a centered grayscale lock icon and a "Locked" tooltip, instead of the real card component.

**Resource unlock restrictions**: `HQ_RESOURCE_UNLOCKS` in `constants.js` maps each HQ type to the resource keys it makes visible in the header bar (Camp: food, wood, faith; Settlement: stone; Village: knowledge, copper; Town: iron; City: gold). `game_screen.vue` filters `HEADER_RESOURCES` against unlocked resources for the current HQ type.

**Column headers**: Josefin Sans uppercase labels (0.7rem, bold, accent at 0.75 opacity) centered above each column, with no border and no extra bottom margin.

### Building Cards (`src/components/buildings/`)

Per-building card components. Each receives `buildingKey`, `img`, and `building` props. `building` is a plain snapshot from `ui.buildings[key]` (built by `syncAllBuildings`/`syncBuilding`: `level`, `isUnbuilt`, `isConstructing`, `constructionRemaining`, `constructionDuration`, `levelUpCost`, `levelUpCostEntries`, `isProducer`, `workers`, `maxWorkers`, `isEmpty`, `isFull`), never the engine model instance. The HQ card reads its own snapshot from `ui.hq`.

**`base_card.vue`** — Shared card layout: flex row (top-aligned) with thumbnail image (100cqh, 6.25rem fallback; grayscale while unbuilt) and a level badge overlay (bottom-right, semi-transparent black background, `Azeret Mono` 11cqh / 0.7rem) showing the numeric level, building name (`Jost`, 16cqh / 1rem). Sizing uses container-query units (`cqh`, the card is a `container-type: size` container when supported) with rem fallbacks declared first, so cards scale with the 1/6-column row height. Cards use `--color-bg-surface` background with `--color-border`; the border brightens only while constructing. Accepts optional `nameKey` prop to override the default localization key. Provides a default `<slot>` inside the action row for inline custom content (e.g. market/academy modal buttons), plus a named `below-action` slot for non-producer buildings (currently unused). A `?` help icon button sits in the top-right corner of each card (circular, muted accent border, brightens on hover). Hovering shows a "Help" tooltip; clicking opens `BuildingHelpModal` with the building's name and description. Accepts `showLevel` prop (default `true`); when false, the level badge is hidden (used by HQ card). Accepts `showBuildAction` prop (default `true`); when true, shows an action row: a build button (build icon, "Build {Name}" tooltip) at level 0, or a level-up button (upgrade icon, "Increase level" tooltip) at level > 0. The level-up tooltip adds a second line with the next level's gain where one applies: storage capacity (storehouse), faith granted (monument), population (house), worker capacity (producers), fee reduction (market, omitted once the next level no longer lowers it) and faith rate (altar). When disabled, the tooltip explains why (territory full or insufficient resources). Hovering the cost items shows a delayed tooltip with full amounts (`.action-cost-tooltip`). Both the slot and the action row render when level > 0. Buildings in `DOWNGRADABLE_BUILDINGS` also show a downgrade button (rotated upgrade icon, "Decrease level" tooltip) when territory is full, the largest single resource in `ui.expansionCost` exceeds storage capacity (so expanding is impossible), the level is > 0 and the building is not constructing; clicking it calls `downgradeBuilding`. Clicking the button deducts the cost from colony resources and starts a construction timer. Cost comes from the snapshot's `levelUpCost` (copied from the model's `levelUpCost` getter at sync time). During construction (`building.constructionRemaining > 0`), the button itself becomes the progress indicator: a semi-transparent gold `::before` overlay fills left-to-right (driven by `--progress` CSS variable), the icon is replaced by a MM:SS countdown, and the cost items hide. The card border brightens to the accent color while constructing. The level increments only when the timer reaches zero.

**`headquarters_card.vue`** — Wraps `BaseCard` with `:show-level="false"` (level badge hidden), passes a computed `nameKey` of `building.headquarters.${type}` to display the HQ type name (Camp, Settlement, etc.) instead of the generic building name. Injects `ui` and `actions` (provided by `game_screen.vue`) for reactive UI reads and player action dispatch; all HQ data comes from `ui.hq` and `ui.expansionCost`. Displays two action rows (upgrade first, then expand):
- **Upgrade** — upgrade icon, "Upgrade to {next type}" tooltip. Costs `hq.upgradeCost`. Starts a construction timer; advances HQ type on completion. Hidden at max type (City). Disabled when resources insufficient or HQ is busy.
- **Expand Territory** — territory icon, "Expand territory" tooltip with a "+N slots" line (`HQ_TERRITORY_PER_LEVEL`). Costs `state.expansionCost` (food + wood): `hq.levelUpCost` reduced by Expansion research (`BONUS_EXPANSION_COST`). Starts a construction timer; level increments on completion. Disabled when resources insufficient or HQ is busy (either timer active). Both action buttons become progress indicators (gold fill overlay + countdown) while their timer is active. The two timers are mutually exclusive.

**`house_card.vue`** — Thin wrapper around `BaseCard` with no custom content. Worker recruitment is handled by `worker_assignment_row.vue`.

Each action is a horizontal row: a square icon-only button (28cqh, 1.75rem fallback) with the action image (`build.png`, `upgrade.png`, `territory.png` from `public/img/other/`; downgrade reuses `upgrade.png` rotated 180°) + cost items displayed outside the button to its right. Buttons use the `.tooltip` class with localized `data-tooltip` for hover labels. Cost rendering iterates the `Cost.entries` getter (a `Map<string, number>` of non-zero resources).

**`worker_assignment_row.vue`** — Reusable component rendered by `base_card.vue` for `Producer` buildings (academy, temple, farm, woodcutter, quarry, copperMine, ironMine, goldMine) via `building.isProducer` flag. Displays a red minus button, worker icon with `current/max` count, and green plus button. Max workers = `level × WORKERS_PER_LEVEL` (5). Injects `ui` and `actions` to read `ui.idleWorkers` and dispatch worker assignment/unassignment. Minus disabled at 0 workers; plus disabled when at building capacity and no idle workers available and cannot recruit (no afford or at population cap). When pressed, plus uses an idle worker if available; otherwise recruits a new worker (spending `WORKER_RECRUIT_COST`) and assigns it directly. While there are no idle workers, the plus tooltip reads "Recruit worker" and the food recruit cost is shown to the right of the row (`.recruit-cost`), hidden when the building is full or the population cap is reached, and shown in red (`.action-cost-short`) when food is the only thing missing. Ctrl+click (or Cmd+click on Mac) on plus/minus assigns/unassigns up to `BULK_WORKER_AMOUNT` (10) workers at once.

**Adding a new building card**: Create `{building}_card.vue` wrapping `BaseCard`, add custom content via the slot, and register it in the `CARD_COMPONENTS` map in `game_screen.vue`.

### Game State (`src/js/engine/state.js`)

Central state container instantiated once per game session. Plain JS class — **not** wrapped in `reactive()`. The engine operates on vanilla objects with zero Proxy overhead. `game_screen.vue` maintains a `shallowReactive` UI view model (`ui`) that is synced from the plain engine state through partial sync functions, each replacing one slice of `ui`: `syncSeason`, `syncResources` (amounts, storage cap, research storage/habitation bonuses, idle workers, caps, HQ type), `syncProduction` (production, consumption, net rates, multipliers, productivity, game speed), `syncAllBuildings` / `syncBuilding(key)` (building snapshots), `syncHQ` (HQ snapshot + expansion cost), `syncAcademy`, `syncMarket` (base prices + fee), `syncEvents`, `syncChallenges` (active challenge, choices, challenge modal, active blessing/punishment entries) and `syncTutorial`.
- `syncUI()` — full sync, runs all of them except `syncBuilding`. Called on every 1-second `gameTick`; from the rAF loop on a frame that caught up after a background tab, saw a construction/HQ upgrade/research complete, saw a blessing expire, or paused the game; and after the blessing, punishment, win-continue and tutorial-dismiss actions.
- Player actions in the `actions` object call only the partial syncs they affect (e.g. `assignWorkers` → resources, production, that building, events, tutorial; `dismissEvent` → events).
- `syncTimers()` — fast path from the rAF loop, throttled to ~20fps via `UI_SYNC_INTERVAL` (50 ms). Updates season elapsed/season/year, snapshots of constructing buildings and the HQ, research timers, event countdowns (with the challenge "requirements met" flag), blessing/punishment timeouts, the active challenge timer, and re-syncs challenges when the challenge modal changed.

Constructor receives a `Meta` instance (first) and a `Colony` instance (second). Created by `app.vue` via either `State.fromJSON(savedData)` (Continue from home) or `new State(createInitialMeta(), createInitialColony())` (new game; marked tutorial-complete when `storage.tutorialCompleted` is set, then `update(0)`), or restored by `game_screen.vue` for the pause-menu Load and handed to `app.vue` with the `restart` event, then held in a `shallowRef` (so Vue never wraps it in a proxy) and passed as `initialState` prop to `game_screen.vue`.

**Save/Load**: `State.toJSON()` → `Meta.toJSON()` + `Colony.toJSON()` (which calls `Season.toJSON()`, `Resources.toJSON()`, `Buildings.toJSON()` (iterates all 20 buildings' `toJSON()`), `Events.toJSON()`), plus the edge-detection state (`resourcesAtCap`, `resourcesNegativeProduction`, `hadIdleWorkers`) and `challengeModal`. `State.fromJSON(data)` reverses the process using `Meta.fromJSON()` (forcing the tutorial complete and clearing its saved popups if this device already completed it), `Colony.fromJSON(data, BUILDING_CLASS_MAP)`, restores the edge-detection sets (so loading does not re-fire warnings already in the past list) and the challenge modal, re-pauses the game if a challenge or tutorial modal was open at save time, rebuilds the translated names in upcoming event parameters in the current language (`_relocalizeFutureEvents()`, since they are saved pre-translated and the browser language may have changed), then calls `update(0)` to rehydrate derived fields; returns `null` on any error. Stored in `localStorage` via the `storage.savedGame` getter and `storage.writeSavedGame()`.

**Provide/inject**: `game_screen.vue` calls `provide('ui', ui)`, `provide('actions', actions)`, `provide('openResearchModal', fn)`, `provide('openMarketModal', fn)`, and `provide('openChallengeModal', fn)` (provided but not injected anywhere). Components `inject('ui')` for reactive reads from the view model, `inject('actions')` to dispatch player actions (`levelUpBuilding`, `downgradeBuilding`, `expandTerritory`, `upgradeHeadquarters`, `recruitWorker`, `assignWorkers`, `unassignWorkers`, `startResearch`, `executeTrade`, `dismissEvent`, `dismissAllPast`, `selectBlessing`, `acknowledgePunishment`), `inject('openResearchModal')` to open the research modal (used by `academy_card.vue`), and `inject('openMarketModal')` to open the market modal (used by `market_card.vue`). Clicking a challenge event opens the challenge detail modal directly through `handleEventAction()` in `game_screen.vue`. Affordability checks use the `canAffordCost(resources, cost)` utility from `utils.js` instead of the `Resources.canAfford` method.

**Structure**: `state.meta.{ version, createdDateTime, updatedDateTime, challenges, gameSpeed, tutorial }`, `state.colony.{ year, season, idleWorkers (derived getter), resources, buildings, events }` (`season` is a `Season` model with `currentSeason`, `seasonElapsed`, and boolean getters `isWarm`/`isCold`). Derived per-tick values live on `State` itself, not on the colony, and are not saved: `production`, `consumption`, `productivity`, `seasonMultipliers` (`{ food, wood }`), `productionMultipliers` (per resource) and `consumptionMultipliers` (`{ food, wood }`) — the multipliers are kept for the header tooltips. Other `State` fields: `paused` (set by tutorial and challenge modals), `challengeModal`, the edge-detection trackers `_resourcesAtCap`, `_resourcesNegativeProduction` and `_hadIdleWorkers`, and `_constructingKeys` / `_hqUpgrading` (so construction ticks only iterate active timers). Getters: `expansionCost` (HQ `levelUpCost` reduced by Expansion research) and `_constructionDurationMult` (Construction research and the Rapid Construction blessing stack multiplicatively, e.g. 50% + 50% → 25% of the base duration; applied to building level-ups, territory expansion and HQ upgrades, not research). `productivity` — ratio (0 to 1) multiplied into all production rates; set to 0 when no workers exist; otherwise starts at 1 (100%) and is reduced when food/wood has negative net production, proportional to deficit ratio (uncovered consumption / total consumption) scaled by `SHORTAGE_MAX_PENALTY`; worst-of when both are negative; ephemeral, recalculated each tick. Method: `netProduction(resource)` — returns `production[resource] − (consumption[resource] ?? 0)`, used by `State.update()` for negative production detection.

- `resources` (`Resources`) — current amounts with public fields: `territory`, `workers`, `food`, `wood`, `stone`, `copper`, `iron`, `gold`, `faith`, `knowledge`, `territoryBonus` (bonus territory slots granted by blessings, added to effective territory cap). Methods: `canAfford(cost)` (returns `true` if all cost fields are covered), `deduct(cost)` (subtracts cost fields in place).
- `state.production` (`Production`) — per-second rates with public fields: `food`, `wood`, `stone`, `copper`, `iron`, `gold`, `faith`, `knowledge`. Ephemeral (recalculated each tick, not persisted).
- `state.consumption` (`Consumption`, `src/js/models/consumption.js`) — per-second worker upkeep with fields: `food`, `wood`. Ephemeral (recalculated each tick by `State.update()`, not persisted).
- Storage caps live on the buildings that own them: `buildings.storehouse.storageCap(storageBonus)` returns the shared cap for food/wood/stone/copper/iron/gold, `buildings.headquarters.territoryCap` returns territory cap, and `buildings.house.workersCap` (cached each tick) returns worker cap. Faith and knowledge are unbounded.
- `buildings` (`Buildings`) — container with public fields keyed by camelCase building name. Each field holds a class instance extending `Building` (base class with `level`, `constructionRemaining`, `constructionDuration`; getters `isUnbuilt`, `isConstructing`; methods `levelUp(cost, durationMult)` (starts timer with optional research multiplier, returns duration), `advance(delta)` (ticks timer, returns `true` on completion and increments level)) or `Producer` (extends `Building`, adds `workers` defaulting to 0; getters `maxWorkers`, `isEmpty`, `isFull`). `constructionRemaining > 0` means the building is under construction; `constructionDuration` stores the total build time for progress calculation. Getter `totalLevels` returns the sum of all building levels excluding headquarters (used as current territory count). Getter `pendingTerritory` returns the count of non-HQ buildings currently under construction (used to reserve territory). The 8 worker-assignable buildings (academy, temple, farm, woodcutter, quarry, copperMine, ironMine, goldMine) extend `Producer`; all others extend `Building` directly. `Headquarters` also has `type`, `upgradeRemaining`, `upgradeDuration` (for type upgrade timer), getters `isUpgrading`, `isMaxType`, `territoryCap`, `upgradeCost` (returns `Cost|null` based on current type), and `nextType` (returns next type string or `null`); methods `upgradeType(cost, durationMult)` (starts type upgrade timer with optional research multiplier, returns duration), `advanceUpgrade(delta)` (ticks upgrade timer, advances type on completion). All 20 building keys are defined as `BUILDING_*` enums in `enums.js` (e.g. `BUILDING_FARM`, `BUILDING_COPPER_MINE`) and used as computed-property keys throughout `constants.js`, `balancing.js`, and `game_screen.vue`. All 20 building classes have a getter `levelUpCost` that returns a `Cost` using `cost` and `multiplier` from `BUILDING_UPGRADES` (HQ: `cost × m^(level-1)`, others: `cost × m^level`). Individual building classes live in `src/js/models/buildings/`.
- `Cost` (`src/js/models/cost.js`) — multi-resource cost holder with properties: `food`, `wood`, `stone`, `copper`, `iron`, `gold`, `knowledge`, `faith` (all default 0; `Resources.canAfford`/`deduct` and `canAffordCost` check every one). Getters: `entries` (returns a `Map<string, number>` of non-zero resources), `toSeconds` (derives build time in seconds from resource weights defined in `RESOURCE_TIME_WEIGHTS`, raised to `RESOURCE_TIME_EXPONENT`). Method: `multiplyFloor(factor)` (returns a new `Cost` with each resource multiplied by `factor` and floored via `floorWithTolerance` from `utils.js`, so exact whole-number products such as `50 × 1.4²` don't floor one unit low).

All initial values declared via `createInitialMeta()` (a `Meta` instance) and `createInitialColony()` (a `Colony` instance, delegating to `createInitialColonyBasic()`) in `src/js/engine/constants.js`, using numeric values from `src/js/engine/balancing.js`. `createInitialColonyAdvanced()` builds a late-game colony (city HQ, many workers) and is only used by tests. `BUILDING_CLASS_MAP` maps all 20 building keys to their class constructors.

### Player Actions (`State` methods in `src/js/engine/state.js`)

All game state mutations are centralised in `State`. Each method guards preconditions, applies the mutation, and calls `this.update(0)` to recalculate derived values.

- `levelUpBuilding(buildingKey)` — deducts `levelUpCost`, starts a construction timer (`constructionRemaining`). Territory is reserved immediately via `pendingTerritory`. Level increments when the timer reaches zero. Blocked when territory is full or already constructing.
- `downgradeBuilding(buildingKey)` — instantly reduces a producer building's level by 1, freeing a territory slot. Excess workers above the new capacity are returned to idle. Only allowed on `DOWNGRADABLE_BUILDINGS` (10 buildings: the 8 worker-assignable producers plus market and altar) and only when territory is full. Blocked when level is 0 or building is constructing.
- `expandTerritory()` — deducts `expansionCost` (`hq.levelUpCost` reduced by Expansion research), starts a construction timer. Level increments on completion. Blocked when HQ is busy (either timer active).
- `upgradeHeadquarters()` — deducts `upgradeCost`, starts a type upgrade timer (`upgradeRemaining`). HQ type advances on completion. Blocked when HQ is busy.
- `recruitWorker()` — delegates to `_recruit()` (increments `resources.workers`); `colony.idleWorkers` updates automatically (derived getter). Blocked when can't afford or at population cap.
- `assignWorkers(buildingKey, count)` — assigns up to `count` workers to the building. Uses idle workers if available, otherwise recruits via `_recruit()`. Plays sound and calls `update(0)` once at the end. Blocked per-iteration when building is full or when no idle workers and recruitment fails.
- `unassignWorkers(buildingKey, count)` — moves up to `count` workers (or all remaining) from the building back to idle. Calls `update(0)` once.
- `dismissWorkers(count)` — permanently removes up to `count` idle workers from the colony. Decrements `resources.workers`, dismisses population-limit event if below cap, calls `update(0)`.
- `_recruit()` — shared helper: deducts `WORKER_RECRUIT_COST`, increments `resources.workers`, plays sound, fires population-limit event if at cap. Returns `boolean`.
- `_playAssignSound(buildingKey)` — plays building-specific worker assignment sound (farm/academy/woodcutter/temple/mines).
- `startResearch(key)` — validates preconditions (not active/completed, academy level met, can afford), deducts cost, starts timer via `buildings.academy.start()`, creates a future event (`EVENT_TYPE_RESEARCH_COMPLETE`). Blocked when insufficient resources. Tier prerequisites (tier N requires tier N-1) are not checked here — only the research modal enforces them.
- `advanceResearch(delta)` — decrements `remainingSeconds` on all active researches. When a timer reaches zero, calls `academy.complete(key)`, dismisses the future event, and plays `SND_RESEARCH_COMPLETED`. Collects completed keys before processing to avoid mutating the Map during iteration. After any completion it calls `update(0)` and dismisses the population-limit past event if workers are now below the (possibly raised) `workersCap`.
- `executeTrade(resource, direction, amount)` — delegates to `Market.executeTrade(resource, direction, resources, storageCap, amount)`. Calls `this.update(0)` on success to recalculate derived values.
- `selectBlessing(blessingIndex)` — player action from the reward modal. Validates active challenge and modal state. Gets the chosen blessing, calls `challenges.complete(blessing)`, applies the blessing via `_applyBlessing()`, dismisses the challenge event. If all challenges are completed, shows the win modal; otherwise unpauses.
- `acknowledgePunishment()` — player action from the failure modal. Dismisses the challenge event, calls `challenges.fail(punishment)` (resets timers), applies the punishment via `_applyPunishment()`, unpauses.
- `continueAfterWin()` — player action from the win modal. Unpauses the game and clears the challenge modal.
- `advanceChallenges(delta)` — advances blessing/punishment timeouts, activates the next pending challenge if none is active, advances active challenge timers. When delay expires, transitions to `started` and fires a non-dismissable future event with `action: 'openChallengeModal'`. When timeout expires, resolves via `_resolveChallengeTimeout()`. When a blessing expires, calls `update(0)` so cached effects (the Blessed Markets 0% fee) end immediately; the rAF loop also does a full `syncUI()` on that frame so the market fee shown matches.
- `areChallengeRequirementsMet()` — checks all active challenge requirements (faith, building levels, resources, workers) against current colony state. Returns boolean. Also drives the "requirements met" highlight on the challenge event row.
- `_resolveChallengeTimeout()` — on timeout, completes the challenge if requirements are met, otherwise fails it. `_completeChallenge()` first spends the requirements via `_deductRequirements()` (removes the required faith and resources, and sacrifices the required workers; building-level requirements are not consumed), then pauses and shows the reward modal. `_failChallenge()` pauses and shows the failure modal.
- `_applyBlessing(blessing)` — applies instant blessing effects: `GIFT_FROM_THE_HEAVENS` grants resources (capped at storage), `HOLY_EXPANSION` adds to `resources.territoryBonus`.
- `_applyPunishment(punishment)` — applies instant punishment effects: removes fraction of faith, removes fraction of bounded resources, sacrifices workers, downgrades random building levels.
- `_sacrificeWorkers(count)` — removes workers: first from idle pool, then randomly unassigned from producer buildings. Clamped to available workers. Dismisses population-limit event if below cap.
- `_buildingName(buildingKey)` — returns the localized display name for a building. For headquarters, resolves to the HQ type name; for others, uses `t('building.' + key)`.
- `advanceSeason(delta)` — advances `Season.advance(delta)`, which returns how many times the season flipped (a large catch-up delta can flip more than once). Each warm arrival adds a year. On any flip it plays the season sound, replaces the previous season-changed past event with the new season's, and triggers the season tutorial popup.
- `checkTutorial()` — called after every production step. Auto-advances past every step whose `check(buildings)` is already satisfied; once all steps are done it waits until every tutorial popup has been dismissed, then marks the tutorial complete, sets `storage.tutorialCompleted` and logs analytics (first completion on this device only). Also re-triggers the HQ upgrade popup for older saves once the HQ is past camp.
- `_triggerTutorialModal(key)` / `dismissTutorialModal()` — show a tutorial popup once (pausing the game) or queue it behind the current one; dismissing records it, shows the next queued popup, and unpauses only when no tutorial or challenge modal remains. No popups fire once this device has completed the tutorial.

### Events (`src/js/models/events/event.js`, `event_future.js`, `event_past.js`, `events.js`)

Event system for notifying the player of upcoming threats and past occurrences. Events live on `Colony.events` and support serialization via `toJSON()` for save/load.

**`Event`** — Abstract base class with common fields: `id` (auto-assigned), `type` (event type constant, e.g. `EVENT_TYPE_SEASON_CHANGED`, `EVENT_TYPE_BUILDING_UPGRADE`), `textKey` (i18n key), `icon` (full image path from `assets.js`, e.g. `IMG_RESOURCE_FOOD`), `params` (string array for positional i18n interpolation, default `[]`), `buildingKey` (building key for construction event lookup, default `null`), `researchKey` (research key for research event lookup, default `null`), `action` (string action identifier triggered on event click, default `null` — used by challenge events with value `'openChallengeModal'`). Method: `toJSON()` (serializes all fields).

**`EventFuture`** — Extends `Event`. Adds `remainingSeconds` (countdown until event fires). Method: `advance(delta)` (decrements `remainingSeconds`, clamped at 0). Overrides `toJSON()` to include `remainingSeconds`.

**`EventPast`** — Extends `Event`. No additional fields.

**`Events`** — Array-backed container with methods:
- `addFuture({ type, textKey, icon, params, buildingKey, researchKey, action, remainingSeconds })` — creates an `EventFuture` with countdown
- `addPast({ type, textKey, icon, params, buildingKey, researchKey })` — creates an `EventPast`
- `convertToPast(buildingKey, data)` — finds the future event matching `buildingKey`, removes it, and adds a past event with the given data
- `dismissFutureByBuildingKey(buildingKey)` — removes a future event by building key (used when non-HQ buildings complete construction)
- `dismissFutureByResearchKey(researchKey)` — removes a future event by research key (used when research completes)
- `dismissFutureByType(type)` — removes a future event by type (used when challenge events are dismissed)
- `dismiss(id)` — removes event by id (uses `splice` for Vue reactivity)
- `dismissPastByType(type)` — removes all past events matching the given type
- `dismissPastByTextKey(textKey)` — removes all past events matching the given i18n key (used for negative production recovery)
- `dismissAllPast()` — removes all past events
- `hasPastEvent(type)` — whether a past event of the given type exists (used to avoid duplicate population-limit events)
- `sortedFuture` (getter) — returns the internal `future` array, kept sorted by `remainingSeconds` ascending via binary insertion in `addFuture` (callers must not mutate it)
- `sortedPast` (getter) — returns the internal `past` array, most recent first (callers must not mutate it)
- `advance(delta)` — decrements `remainingSeconds` on `EventFuture` items, clamps at 0 (does not auto-convert to past)
- `toJSON()` / `static fromJSON(data)` — serialize and restore the events container (future, past, nextId) for persistence

Called from the `progressTick` loop (`requestAnimationFrame`, ~60 fps) in `game_screen.vue` via `state.advanceEvents(delta)`, alongside `advanceSeason`, `advanceConstruction`, `advanceResearch`, and `advanceChallenges`.

**UI**: Displayed as a 5th column in `game_screen.vue` alongside the 4 building columns (building columns `flex: 1`, events column `flex: 0.75` so buildings get more room). Four sub-sections: "Active Blessings" (ongoing blessing effects with countdown timer, shown when any are active), "Active Punishments" (ongoing punishment effects with countdown timer, shown when any are active), "Upcoming" (future events with gold countdown timer), and "History" (past events, with a "Clear all" button that asks for confirmation before dismissing all). Event rows share one style (icon + text, gold left-border accent). Blessing, punishment and upcoming rows end with a countdown; upcoming rows with an `action` are clickable and show a chevron, and the challenge row is highlighted (`.event-row--met`) while its requirements are currently met. Only past rows have a dismiss (×) button. Past warnings for storage cap, negative production and idle workers also clear themselves when the condition ends, and population/territory limit events clear when the limit is lifted. Empty state shown when no events exist.

### Tutorial System

Step-by-step guided tutorial for new players, active from game start until completion.

**Model** — `Tutorial` class (`src/js/models/tutorial.js`) with `currentStep` (number), `completed` (boolean), `dismissedModals` (Set<string>), `activeModal` (string or null), and `pendingModals` (ordered string array). Active and pending modals are saved (unknown or already-dismissed keys are dropped on load); loading restores the active popup and keeps the game paused. Getters: `isActive`, `allStepsCompleted`, `allModalsDismissed`. Method: `toJSON()`. Lives on `state.meta.tutorial`. Completion requires all steps done and all 4 popups dismissed.

**Per-device completion** — completing the tutorial sets `storage.tutorialCompleted`. From then on, new games start with the tutorial already complete (`app.vue`), loading an older save marks it complete and clears its saved popups (`State.fromJSON`), and tutorial popups are never triggered.

**Steps** — `TUTORIAL_STEPS` constant in `constants.js` — 15 sequential steps, each with `textKey` (i18n key), `hintKey` (i18n key for the secondary hint line), `building` (optional building key whose image is shown), and `check(buildings)` function that returns `true` when the step's objective is met. Steps guide the player through building a house, farm, and woodcutter, assigning workers, upgrading buildings, building an altar, expanding territory, and upgrading the headquarters.

**Modals** — `TUTORIAL_MODALS` constant in `constants.js` — 4 reactive modal definitions keyed by `TUTORIAL_MODAL_*` enums (`SEASON_CHANGED`, `NEGATIVE_PRODUCTION`, `HQ_UPGRADE`, `CHALLENGE_STARTED`). Each has `titleKey` and `bodyKey` for localization. Triggered by game state transitions (e.g. first season change, first challenge start) and shown once (tracked via `dismissedModals`). A trigger that fires while another tutorial modal is open joins the saved queue and appears as soon as the current popup is dismissed. `checkTutorial()` also recovers an undismissed HQ upgrade popup from older saves once the HQ is past camp.

**UI** — `TutorialBanner` (`src/components/tutorial/tutorial_banner.vue`) displays the current step at the bottom of the game screen: optional building icon, step text and hint line. It is keyed by the step number inside a `<Transition>`, so each new step animates in; no step counter is shown. Rendered while the tutorial is active. `TutorialModal` (`src/components/tutorial/tutorial_modal.vue`) shows educational popups triggered by state transitions, rendered whenever a tutorial popup is active.

### Tick System (`State.update()` in `src/js/engine/state.js`)

Core game loop that generates resources over time. `game_screen.vue` runs a main `setInterval` (1 second, `TICK_INTERVAL`) that calls `state.update(deltaSec)` for production/consumption, and a `requestAnimationFrame` loop (~60 fps, `progressTick`) that calls `state.advanceSeason(delta)`, `state.advanceConstruction(delta)`, `state.advanceResearch(delta)`, `state.advanceEvents(delta)`, and `state.advanceChallenges(delta)` for smooth visual progress. Both use `performance.now()` for delta calculation. The main `gameTick` also calls all five progress methods (`advanceSeason`, `advanceConstruction`, `advanceResearch`, `advanceEvents`, `advanceChallenges`) as a fallback for backgrounded tabs where `requestAnimationFrame` pauses. Elapsed real time is converted by `gameDelta()`: gaps up to `MAX_CATCH_UP_GAP` (5 minutes real time, e.g. Chrome's once-a-minute throttled timers in hidden tabs) are credited in full (bounded by `MAX_CATCH_UP_DELTA` against out-of-range saved speeds), and longer gaps (sleep/wake) are credited as a single `MAX_TICK_DELTA` (5 game-seconds) step. `catchUp()` simulates a gap in steps of at most `MAX_TICK_DELTA` game-seconds, interleaving production and progress per step, and stops early if a modal pauses the game mid-gap. `gameTick` includes progress when the tab is hidden or the rAF clock is more than `TICK_INTERVAL` behind; `progressTick` hands a frame gap longer than `TICK_INTERVAL` (first frame back from a background tab) to `catchUp()` for both clocks, so production and progress for that gap stay in step. While paused, both clocks stay frozen: `markPauseStart()` records the pause start once (after the step that paused, at pause-menu open, or in the paused branch of either loop), and `resumeClocks()` — called by every unpause path (tutorial dismiss, blessing, punishment, win-continue, pause-menu close; closing the pause menu restarts both loops but leaves the game paused while a tutorial or challenge modal is still showing, and dismissing that modal unpauses) — shifts `lastTickTime` and `lastProgressTickTime` forward by the paused duration, so no paused time is credited and production earned before the pause is kept.

**Construction timers**: `advanceConstruction(delta)` runs inside the `requestAnimationFrame` loop (`progressTick`) for smooth visual progress (~60 fps). It decrements `constructionRemaining` on all buildings; when a timer reaches zero, the building's level increments and `constructionDuration` resets. For HQ territory expansion, the future event is converted to a past event via `events.convertToPast()`. For all other buildings, the future event is simply removed via `events.dismissFutureByBuildingKey(key)`. When a storehouse completes, all resource-limit past events are dismissed. When a house completes, all population-limit past events are dismissed. When a monument completes, `MONUMENT_FAITH_PER_LEVEL × newLevel` faith is added to `colony.resources.faith`. The HQ type upgrade timer (`upgradeRemaining`) is ticked separately; on completion, `hq.type` advances to the next tier (no event fired for type upgrades). The next `update()` call (1-second interval) picks up the new level for storage cap/production recalculation.

**Territory & storage cap recalculation**: Each tick recalculates `resources.territory` via `buildings.totalLevels + buildings.pendingTerritory` (sum of all building levels plus buildings under construction — each counts as one territory slot), then caches `buildings.house.workersCap` via `buildings.house.populationCap(habitationBonus)` (`level × (HOUSE_POPULATION_PER_LEVEL + habitationBonus)`, where `habitationBonus` is the cumulative flat bonus from completed Habitation researches). Territory cap is the sum of `buildings.headquarters.territoryCap` (`level × HQ_TERRITORY_PER_LEVEL`) and `resources.territoryBonus` (granted by the Holy Expansion blessing). All 6 resource caps (food, wood, stone, copper, iron, gold) via `buildings.storehouse.storageCap(storageBonus)`, which delegates to `storageCapacity(level, storageBonus)` in `utils.js` (also used by the storehouse card tooltip) (`floor(STOREHOUSE_BASE_CAPACITY × STOREHOUSE_CAPACITY_MULTIPLIER^level × (1 + storageBonus))`, where `storageBonus` is the cumulative fractional bonus from completed Storage researches). All balancing values in `src/js/engine/balancing.js`. Building level-ups (except HQ) are blocked when `resources.territory >= headquarters.territoryCap + resources.territoryBonus`; HQ is exempt since it is the only building that increases max territory.

**Production formula**: Computed in `_computeProductionRates()` (state.js) in two stages. **Stage 1 — base rates**: for each building in `PRODUCTION_RATES` (balancing.js), base rate = `workers × config.rate` (or `level × config.rate` for passive buildings like altar). **Stage 2 — per-resource multipliers**: each resource starts with multiplier `1`, then research bonuses (`BONUS_FOOD_PRODUCTION`, `BONUS_MINING_PRODUCTION`, etc.), worker productivity (`BONUS_WORKER_PRODUCTIVITY` from Transportation research, bounded resources only), active blessing productivity boosts (e.g. `FERTILE_SOIL` for farms, `CELESTIAL_PROSPERITY` for all producers), active punishment productivity reductions (e.g. `CROP_FAILURE` for farms, `VOLCANO` for all producers), and season modifier (food only, `±SEASON_WARM/COLD_FOOD_MODIFIER`, amplified/softened by `FAVORABLE_WEATHER` blessing) are added additively. The final raw rate per resource is `baseRate × multiplier`. The productivity penalty (from `_computeGeneralProductivity`) is applied externally in `update()`: `finalRate = rawRate × productivity`. Rates are stored on `state.production` (per-second) for UI display, then scaled by `deltaSec` when applied to `colony.resources`. Resources (except faith and knowledge, which are unbounded) are capped at `buildings.storehouse.storageCap(storageBonus)` after application.

**Worker consumption**: Computed in `_computeConsumptionRates()` right after production rates in `update()`; production is added to stock first, then upkeep is deducted. Every worker (idle and assigned) consumes `WORKER_FOOD_CONSUMPTION × max(0, 1 − BONUS_FOOD_CONSUMPTION)` food/sec and `WORKER_WOOD_CONSUMPTION × max(0, 1 − BONUS_WOOD_CONSUMPTION − (1 − seasonMultipliers.wood))` wood/sec. The wood research bonus and the seasonal modifier (`SEASON_WARM_WOOD_MODIFIER` −20% in warm, `SEASON_COLD_WOOD_MODIFIER` +20% in cold, shifted by the `FAVORABLE_WEATHER` blessing) stack additively, not multiplicatively. If resources are insufficient, they are clamped to 0. Skipped when `delta === 0` or no workers exist.

**General productivity**: Computed in `_computeGeneralProductivity()` (state.js). When food or wood has negative net production (tracked by `_resourcesNegativeProduction`, a one-tick-delayed edge-detection set), productivity is reduced proportionally to the deficit ratio: `1 - (deficit / consumption) × SHORTAGE_MAX_PENALTY`. Uses current-tick raw production rates (before penalty) and current-tick consumption rates to avoid a feedback loop where penalized production locks productivity at zero. The penalty applies to all resource production equally.

**Negative production detection**: After net production is finalized (including worker upkeep subtraction), a `_resourcesNegativeProduction` Set tracks which bounded resources currently have negative net production. When a resource transitions from non-negative to negative, a past event fires (using `RESOURCE_NEGATIVE_PRODUCTION_EVENT_CONFIG` from `constants.js`). When it recovers to non-negative, the corresponding past event is removed via `events.dismissPastByTextKey()` and the resource is removed from the set so future drops can re-trigger. This follows the same edge-detection pattern as `_resourcesAtCap`. The first food or wood drop also triggers the negative-production tutorial popup.

**Idle workers detection**: `_hadIdleWorkers` applies the same pattern to idle workers: an "idle workers" past event fires when the idle count rises above 0 and is dismissed when it returns to 0.

**Base rates** (per worker per second): farm→food 1.0, woodcutter→wood 0.5, quarry→stone 0.3, copperMine→copper 0.2, ironMine→iron 0.1, goldMine→gold 0.05, academy→knowledge 0.1, temple→faith 0.15. Altar→faith 0.1/level/sec (passive). All values defined in `src/js/engine/balancing.js`.

**Tooltips** — Colony items (population, idle workers, territory) use CSS-only tooltips (`.tooltip` class + `data-tooltip` attribute). Resource items, the productivity card and the season indicator use HTML-based rich tooltips (`.resource-tooltip`) that display the name plus amount, capacity, time estimate and rate/modifier breakdown on hover (see Game Header). Both tooltip styles are defined in `src/assets/styles.css`.

### Localization (`src/js/i18n/`)

Each supported language has its own file (`ca.js`, `en.js`, `es.js`, `fr.js`, `it.js`) exporting a flat object with dot-notation keys (e.g. `'screen.home.newGame'`, `'resource.food'`, `'season.warm'`). At startup, `localized.js` reads `navigator.language`, resolves it to a supported locale (defaulting to English), and exports a `t(key, ...params)` helper that looks up strings from the resolved locale. When `params` are provided, positional placeholders (`{0}`, `{1}`, etc.) in the string are replaced with the corresponding values. Components import `t` from `localized.js` and use it in templates (`{{ t('key') }}`, `{{ t('key', param0) }}`) and bound attributes (`:alt="t('key')"`). No hardcoded display text in templates or JS.

### Assets (`src/js/engine/assets.js`)

Auto-generated by `scripts/generate-assets.js` (`npm run generate-assets`). Scans `public/img/`, `public/audio/sound/`, and `public/audio/music/` and exports named constants with prefixes: `IMG_` for images, `SND_` for sound effects, `MUS_` for music tracks. Also exports `IMG_RESOURCE_MAP` (resource key → image path) and `IMG_PUNISHMENT_MAP` (punishment type → image path) for dynamic image lookups. Do not edit `assets.js` manually.

### Format (`src/js/engine/format.js`)

Shared display formatters.

- `formatTime(totalSeconds)` — converts seconds to `MM:SS` or `HH:MM:SS` (hours only when ≥ 3600s). Uses `Math.ceil` rounding. Used by construction timers, research timers, event countdowns, and resource time estimates.
- `formatNumber(n)` — abbreviates large numbers with K/M/B/T suffixes (e.g. 1500 → "1.5K"). Used for resource amounts, worker counts, and territory display.
- `formatNumberFull(n)` — floors and formats with locale thousands separators, no abbreviation (e.g. "123,456"). Used in tooltips that show exact amounts (resource tooltip, cost tooltips, market summary).
- `formatMinutes(totalSeconds)` — converts seconds to a localized "{n} minute(s)" string. Used for blessing/punishment durations in the challenge success and failure modals.
- `formatRate(ratePerSecond)` — formats a per-second rate rounded to two decimals with the localized "/s" suffix (e.g. "1.2/s", "-0.35/s"). Used for the inline rate in header resource boxes.

### Utils (`src/js/engine/utils.js`)

Shared pure helpers used by both engine and components.

- `floorWithTolerance(value)` — floors after absorbing tiny float error, so exact whole-number products (e.g. `45 × 1.4`) don't floor one unit short. Used by `Cost.multiplyFloor` and `storageCapacity`.
- `canAffordCost(resources, cost)` — affordability check against a plain resource snapshot (used by components reading `ui.resources`).
- `marketFeePercent(level)` — market fee in whole percent: base fee reduced per level above 1, floored at the minimum fee (ignores the Blessed Markets blessing). Used by `Market.effectiveTradeFee` and the market card tooltip.
- `storageCapacity(level, storageBonus)` — storehouse cap formula, shared by the storehouse model and its card tooltip.
- `marketTradeQuote(price, direction, lots, fee)` — gold total and resulting price for trading a number of lots; each lot shifts the price first, the price stops at its bounds, and the fee is applied once to the total in integer percent math. Shared by `Market.executeTrade` and the market modal.

### Audio (`src/js/engine/audio.js`)

Singleton `Audio` class managing sound effects and background music. Preloads all audio files from `AUDIO_CONFIG` (in `constants.js`) when a game starts or restarts (`app.vue` calls `preload()`), not at app startup. Per-asset volume levels are configured in `AUDIO_CONFIG`. Preferences (music/sound enabled) are persisted via `Storage`. Registers a `visibilitychange` listener to auto-resume music when the tab becomes visible (workaround for iOS Safari suspending audio in background tabs). A `_gamePaused` flag prevents auto-resume from overriding intentional pauses by game logic.

**Methods**: `preload()`, `playSound(assetPath)` (one-shot effect), `playMusicPlaylist(tracks)` (sequential playlist, cycles back to first after last), `stopMusic()`, `stopMusicPlaylist()` (stops and clears the playlist; used when quitting to the home screen), `pauseMusic()`, `resumeMusic()`, `setMusicEnabled(enabled)`, `setSoundEnabled(enabled)`.

**Helper**: `playTap()` — exported shortcut that plays the button tap sound effect (`SND_BUTTON_TAP`). Used by all interactive UI components.

### Analytics (`src/js/engine/analytics.js`)

Singleton `Analytics` class sending gameplay events to Firebase Analytics (Google Analytics 4). `main.js` calls `init()` at startup; it initializes Firebase with `FIREBASE_CONFIG` (in `constants.js`) unless the hostname is in `ANALYTICS_EXCLUDED_HOSTNAMES` or `isSupported()` reports no support. Events are chained on the initialization promise, so events fired before it settles are still sent; when analytics is disabled or blocked, every call is a silent no-op. Event names and params live in `enums.js` (`ANALYTICS_EVENT_*`, `ANALYTICS_GAME_MODE_*`).

**Methods**: `init()`, `logGameStart(mode)` (`game_start`, sent from `app.vue` `launchGame` (new game, Continue, pause-menu Load and Restart) with mode `new` or `saved`; a corrupt save on Continue from the home screen falls back to a new game and counts as `new`), `logTutorialComplete()` (`tutorial_complete`, sent from `State.checkTutorial` when the tutorial completes).

### Storage (`src/js/engine/storage.js`)

Thin `localStorage` wrapper for persisting user preferences and game state. Exposes `musicEnabled` and `soundEnabled` as getter/setter pairs (default `true`). Used by `Audio` to persist toggle state across sessions. Also exposes `autosaveEnabled` (default `false`) and `autosaveInterval` (default `AUTOSAVE_DEFAULT_INTERVAL`, also used when the stored value is empty or not a finite number; clamped to `AUTOSAVE_MIN_INTERVAL`–`AUTOSAVE_MAX_INTERVAL` on read) getter/setter pairs for autosave configuration. Also exposes `tradeAmount` (default `MARKET_TRADE_AMOUNT`) for persisting the market trade lot size, and `tutorialCompleted` (default `false`) recording that this device has finished the tutorial. Exposes a `savedGame` getter (JSON parse, `null` on missing/corrupt data), `writeSavedGame(value)` (JSON stringify; returns `false` when storage is blocked or full) and `deleteSavedGame()` for save/load persistence.

### Research System

Research is an academy-gated tech tree providing cumulative bonus modifiers.

**Model** — Research state is managed directly by the `Academy` class (`src/js/models/buildings/academy.js`), which extends `Producer` with `completed` (`Set<string>`), `active` (`Map<string, Research>`). Methods: `isCompleted(key)`, `isActive(key)`, `canResearch(key)` (requires level ≥ 1, not active, not completed), `start(key, duration)`, `complete(key)`, `completedBonuses(researchTree)` (aggregates `BONUS_*` values using each subcategory's `bonus` entry in the tree; cached and cleared only when a research completes), `toJSON()`. Each active entry is a `Research` (exported from the same file) with `duration` and `remainingSeconds`, and `advance(delta)` returning `true` on completion. Accessed via `colony.buildings.academy`.

**Enums** (`enums.js`) — `RESEARCH_CATEGORY_*` (5 categories, in tree order: colony, resources, religion, military, disasters), `RESEARCH_SUBCATEGORY_*` (18 subcategories, e.g. transportation, construction, storage, habitation, floods, food production, defense, attack, warning), `RESEARCH_*` keys (5 tiers per subcategory, e.g. `RESEARCH_TRANSPORTATION_1` through `_5`), `BONUS_*` types (18, e.g. `BONUS_WORKER_PRODUCTIVITY`, `BONUS_CONSTRUCTION_TIME`, `BONUS_FOOD_PRODUCTION`, `BONUS_HABITATION`, `BONUS_UNIT_DEFENSE`).

**Definitions** (`balancing.js`) — `RESEARCH_TIER_COSTS` holds one base `Cost` per tier (index 0 = T1) and `RESEARCH_SUBCATEGORY_COST_MULTIPLIERS` one price-band multiplier per subcategory; `constants.js` combines them into `RESEARCH_COSTS`. `State.startResearch` sets the duration to `max(1, floor(cost.toSeconds × RESEARCH_TIME_MULTIPLIER))`, without the construction multiplier. Starting any research requires academy level ≥ 1 (flat check, not per-research). Bonuses are defined per subcategory in `RESEARCH_SUBCATEGORY_BONUSES` (also in `balancing.js`), mapping each `RESEARCH_SUBCATEGORY_*` to `{ type: BONUS_*, value: number, [flat: true] }`. Each tier within a subcategory costs progressively more resources.

**Tree** (`constants.js`) — `RESEARCH_TREE` is an ordered array of `{ category, subcategories: [{ key, bonus, researches: [research keys] }] }` (`bonus` is the subcategory's entry from `RESEARCH_SUBCATEGORY_BONUSES`). It drives `Academy.completedBonuses` and `RESEARCH_COSTS` (each research key → `RESEARCH_TIER_COSTS[index].multiplyFloor(RESEARCH_SUBCATEGORY_COST_MULTIPLIERS[subcategory])`); position in `researches` implies the linear prerequisite. `RESEARCH_MODAL_TREE` is the same tree without the disasters category and drives the research modal layout, so the Disasters tab stays hidden until disasters are implemented.

**Modal** (`research_modal.vue`) — Tabbed overlay with category tabs at top, scrollable subcategory sections below. Each subcategory displays a horizontal chain of research nodes connected by arrows. Node states: `completed` (green border + checkmark), `active` (pulsing glow), `available` (brighter border), `locked` (dimmed). Each node shows name and resource cost icons. A "?" help button (`.modal-help-btn`) sits left of the close button and opens `ModalHelpModal` with research help text. Opened via `inject('openResearchModal')` from `academy_card.vue`, and closed automatically by `game_screen.vue` when the academy's level drops below 1 (a punishment can destroy a mid-upgrade academy). Emits `close` on backdrop click, close button, or Escape key.

### Challenges System

Sequential divine challenges forming the game's win condition. State lives on `state.meta.challenges`.

**Model** — `Challenges` container class (`src/js/models/challenges.js`) with fields: `pending` (array of `Challenge`), `active` (`Challenge` or `null`), `completed` (array of `Challenge`), `activeBlessings` (array of `Blessing`), `activePunishments` (array of `Punishment`). Getters: `totalCount`, `allCompleted`. Methods: `activate()` (moves first pending to active), `start()` (transitions active from `activated` to `started`), `complete(blessing)` (marks active complete, stores a copy of the blessing), `fail(punishment)` (resets challenge timers, stores a copy of the punishment so the countdown never drains the challenge's own punishment, which is reused on retry), `advance(delta)` (advances delay/timeout timers). Accessed via `state.meta.challenges`.

**Challenge** (`src/js/models/challenge.js`) — individual challenge with fields: `index`, `status` (`pending`/`activated`/`started`/`completed`), `delay`, `delayElapsed`, `timeout`, `timeoutElapsed`, `requirements` (`{ faith, altar, temple, monument, resources, workers }`), `blessings` (array of 2 `Blessing` choices), `punishment` (`Punishment`). Getters: `isDelayElapsed`, `isTimeoutElapsed`. Method: `reset()` (resets timers and status to `activated` for retry after failure).

**Blessing** (`src/js/models/blessing.js`) — reward with fields: `type` (blessing type enum), `timeout` (duration or `null` for instant), `productivity`, `resources`, `territory`, `construction`, `warm`, `cold` (all nullable, effect-specific).

**Punishment** (`src/js/models/punishment.js`) — penalty with fields: `type` (punishment type enum), `timeout` (duration or `null` for instant), `faith`, `productivityFarm`, `productivityWoodcutter`, `productivityMines`, `productivityGeneral`, `resources`, `workers`, `levels` (all nullable, effect-specific).

**Enums** (`enums.js`) — `CHALLENGE_STATUS_*` (4 statuses: pending, activated, started, completed), `CHALLENGE_*` keys (1–10), `CHALLENGE_MODAL_*` (reward, failure, win), `BLESSING_*` types (10: fertile soil, forest bloom, gift from the heavens, holy expansion, rich mines, celestial prosperity, rapid construction, favorable weather, wisdom of the gods, blessed markets), `PUNISHMENT_*` types (5: crop failure, wildfires, landslide, plague, volcano), `EVENT_TYPE_CHALLENGE_STARTED`.

**Definitions** (`src/data/challenges.json`) — 10 challenge definitions with escalating requirements, 2 blessing choices each, and typed punishments. Loaded by `createInitialChallenges()` in `constants.js`.

**UI field** — `state.challengeModal` (`null`/`CHALLENGE_MODAL_REWARD`/`CHALLENGE_MODAL_FAILURE`/`CHALLENGE_MODAL_WIN`) controls which blocking modal is shown. Game is paused while any challenge modal is visible.

## Visual Design

**Theme**: Earthy & Ancient — warm browns, parchment tones, and aged bronze accents, evoking a torchlit ancient settlement. Inspired by Forge of Empires, Tribal Wars 2, Goodgame Empire.

**Colors**:
- Background: `rgba(22, 18, 14, 1)` (deep umber, aged wood by torchlight)
- Raised surface: `rgba(30, 26, 20, 1)` (dark walnut)
- Panel surface: `rgba(39, 33, 25, 1)` (stone panel)
- Text: `rgba(228, 213, 188, 1)` (warm parchment cream)
- Accent: `rgba(184, 148, 62, 1)` (aged bronze)
- Border: `rgba(184, 148, 62, 0.15)` (subtle warm border)
- Modal overlay: `rgba(0, 0, 0, 0.85)` (no blur)

- Muted UI: `rgba(228, 213, 188, 0.1–0.4)` (parchment-toned)

- Title screen: warm torchlight glow behind title (radial gradient accent)
